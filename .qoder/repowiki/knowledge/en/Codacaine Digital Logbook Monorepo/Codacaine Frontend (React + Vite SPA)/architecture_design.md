The app entry `src/main.tsx` mounts a React root that renders `App`, which is the single cross-child orchestrator: it wraps every route in a nested provider chain (`ThemeInitializer` → `AuthProvider` → `NotesProvider` → `DataSyncInitializer`) so all child modules share auth state, notes overlay state, theme, and an on-login IndexedDB warm-up via `CacheFunctions.syncAllData`. Routing is declared centrally in `App.tsx` using `react-router-dom`, grouping routes into public (`/signin`, `/auth/callback`, `/reset-password`, `/auth/update-password`) and protected (`/dashboard`, `/projects`, `/project/:projectName`, `/stats`, `/streaks`, `/calendar`, `/kanban`, `/today`, `/timeline`, `/notifications`, `/data-portability`) sets guarded by `ProtectedRoute`. Child modules stay isolated by feature folder (`pages/*`, `components/*`, `functions/*`, `hooks/*`, `lib/*`, `context/*`, `CacheFunctions/*`, `Templates/*`) and communicate only through the shared contexts (`AuthContext`, `NotesContext`), the `lib/supabase.ts` client, and the `CacheFunctions` offline queue. Cross-cutting concerns — offline banner/toasts, tour navigation via a custom `dl-tour-navigate` window event, and font/corner style restoration from `localStorage` before first paint — are injected at the top level rather than per-page.
