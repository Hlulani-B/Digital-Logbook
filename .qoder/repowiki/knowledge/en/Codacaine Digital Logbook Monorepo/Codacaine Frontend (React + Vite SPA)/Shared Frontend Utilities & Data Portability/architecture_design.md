Organised as a flat collection of single-purpose modules under `src/lib` plus two feature files under `src/functions`, with no shared internal sub-packages. Dependency direction is one-way: view helpers (`kanban.ts`, `timeline.ts`, `today.ts`) depend on the canonical `CalendarEntry` type from `calendar.ts`; `export.ts` and `import.ts` share a normalised `ExportBundle` shape so round-tripping is symmetric; `api.ts` centralises HTTP requests and pulls the Supabase session via a lazy dynamic import of `supabase.ts`, which itself lazily constructs the `@supabase/supabase-js` client only when credentials are present. Cross-cutting concerns are isolated: `validation.ts` guards auth emails before they reach Supabase Auth, `entryPayload.ts` sanitises legacy notes-shaped payloads leaking into summaries, `projectColorMap.ts` resolves per-project accent colours, and `tour.ts` drives a driver.js walkthrough that communicates with the shell through custom window events (`dl-tour-navigate`, `dl-tour-open-drawer`). Persistent state lives in `localStorage` behind typed getters/setters (`recentlyCreated.ts`, `recentlyViewed.ts`, `aiMessages.ts`, `tour.ts`), each emitting a `CustomEvent` on change so UI components can subscribe reactively without coupling to storage.
