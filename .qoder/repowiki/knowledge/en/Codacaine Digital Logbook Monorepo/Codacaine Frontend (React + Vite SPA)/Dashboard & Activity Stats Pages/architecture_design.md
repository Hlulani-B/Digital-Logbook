Each page is a self-contained React component (Dashboard.tsx, Today.tsx, Calendar.tsx, StatsView.tsx, StreakView.tsx) that owns its own data-loading lifecycle: a `loadSeq` ref guards against concurrent `loadData` calls triggered by mount effects, multiple `cacheSubscribe` listeners, SSE events, and visibility changes. Data is read exclusively from an IndexedDB-backed cache via `cacheGet(CACHE_STORES.ALL_ENTRIES|PROJECTS|ENTRIES, email)`; on first visit with no cache, pages call `syncAllData(email)` to populate it before re-reading. Real-time updates are handled by subscribing to cache stores (`cacheSubscribe`) and by the shared `useSSEEntries` hook in Dashboard. Computed views are derived with `useMemo` (e.g., `getTodaySections`, `calculateStreaks`, `calculateProjectStats`, `computeFieldStats`). Shared UI shell components (`NavBar`, `Header`, `StatCard`, `BarChart`, `DonutChart`, `FieldStatPanel`) are reused across pages. The `ActivityPage` is a thin wrapper that renders `Dashboard` with `defaultView='activity'`. Supporting utilities live under `functions/`: `activity.js` posts to the project service's `/service/activity` endpoint via `request(PROJECT_URL, ...)`, `tone.ts` manages a `dl_tone` localStorage preference and emits prompt instructions for AI-generated greetings/messages, and `voicefeature.js` wraps the Web Speech API to transcribe speech and dispatch natural-language entries through `addNaturalLanguageEntry`. Cross-cutting concerns (auth, routing, caching, color maps, overdue logic) are imported from `@/context`, `@/lib`, and `@/functions/dashboard/*` rather than duplicated.
