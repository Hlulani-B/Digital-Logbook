The root orchestrates five independently deployed Render services (frontend SPA, auth/dashboard/project/profile backends, plus a MkDocs docs site) declared in `render.yaml`, all sharing one Supabase PostgreSQL instance defined under `database_schema/` and migrated via versioned SQL files. The frontend consumes the backend REST APIs through `VITE_*_SERVICE_URL` env vars while also calling Supabase directly for auth; each service reads its own `.env` for `DATABASE_URL`, `SUPABASE_URL`, and provider keys. Cross-cutting concerns are centralized at the root: `package.json` exposes npm scripts (`db:migrate`, `db:backup`, `db:restore`, `format`) that invoke shared CLI tools under `scripts_and_tooling/`, and CI pipelines generate per-service coverage badges committed to `badges/`. Services communicate only over HTTP — there is no shared library or event bus between them — so the contract is the OpenAPI 3 spec served by the project service.
